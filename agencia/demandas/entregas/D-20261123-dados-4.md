## 4. Proposta de alteração em `scripts/insights.py` (não apliquei; só leitura, sem token no JSON)
Problema: hoje `ig_alcance_28d` pede `metric=reach&period=days_28`, que devolve só o total da conta (10046 no último ponto, sem origem). A Meta documenta o breakdown `media_product_type` (valores AD, FEED, REELS, STORY) para `reach` da conta, mas só no modo `metric_type=total_value` (https://developers.facebook.com/docs/instagram-platform/api-reference/instagram-user/insights, citada na demanda; não reli a doc fora da demanda). Esse modo trabalha com `since`/`until` e `period=day`, não com `days_28`.

Proposta (acrescentar uma chamada, manter a atual):
```python
import time
def ig_alcance_formato():
    fim = int(time.time())
    ini = fim - 28 * 86400
    r = get(f'{IG}/insights', metric='reach', period='day',
            metric_type='total_value', breakdown='media_product_type',
            since=str(ini), until=str(fim))
    tv = r['data'][0]['total_value']
    return {
        'janela': '28d',
        'total': tv.get('value'),
        'por_formato': {x['dimension_values'][0]: x['value']
                        for x in tv.get('breakdowns', [{}])[0].get('results', [])},
    }
tenta('ig_alcance_28d_formato', ig_alcance_formato)
```
Garantias, na ordem em que o script já trabalha:
- Gravo só `total` e `por_formato` (números), nunca a resposta crua; nada de `paging` nem URL. O `sem_paging()` e o `assert 'access_token' not in texto` continuam valendo para o JSON inteiro.
- Se a Meta recusar (janela de 28 dias passa do limite do `since`/`until`, ou o breakdown não vale pra essa métrica), `tenta()` grava a mensagem em `erros` e o resto da coleta segue. Falha esperada a verificar: o limite de janela do `total_value` (se for 30 dias ou menos, 28 cabe).
- Só leitura (GET); nenhum token novo; permissão é a mesma `instagram_manage_insights` que já respondeu nesta coleta.
- Não está testado. **Teste antes de comitar:** rodar localmente sem gravar em `dados/` (ou com saída em `/tmp`), ver se `por_formato` vem com AD/FEED/REELS/STORY, só então deixar o workflow `insights.yml` (cron 23h41) coletar.
